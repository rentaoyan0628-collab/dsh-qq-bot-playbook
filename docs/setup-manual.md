# 大肥鱼：从零到能聊天的完整说明书

> 这份是**给人看的**。想给 AI 看的操作手册是 `.agents\skills\` 里那几个 skill。
> 覆盖：SnowLuma → QQ 桥接 → DSH → 插件，四层怎么搭起来，以及每一层坏了看哪里。

---

## 0. 这份文档解决什么

你可能遇到这几种情况：

- 想给自己弄一个 QQ 上的 AI 聊天号，但不知道从哪下手
- 已经有一个了，但它"笨"、"不记得事"、"说话不像人"
- 照着网上的教程装，装到一半不知道下一步干什么
- 装好了，但某个功能不工作，不知道是哪个环节的问题

下面按**从下往上**的顺序讲。每一层都回答三个问题：**它是什么、为什么需要它、坏了怎么办**。

---

## 1. 先看懂这张图

```
        QQ 客户端
            │  你发消息 / 收消息
            ▼
   ┌─────────────────┐
   │   SnowLuma      │  ← 第 1 层：把 QQ 变成标准接口（OneBot v11）
   │  3000 HTTP      │     装一次，配好账号就不用再管
   │  3001 WS        │
   └─────────────────┘
            │
            ▼
   ┌─────────────────┐
   │   qq-bridge     │  ← 第 2 层：可有可无，但装了才"像个人"
   │  3100 控制台    │     语音转文字、传话箱、管理员闸、跨会话记忆…
   └─────────────────┘
            │
            ▼
   ┌─────────────────┐
   │   DSH           │  ← 第 3 层：大脑，跑模型、管会话、调工具
   │  （桌面应用）    │
   └─────────────────┘
            │
            ▼
   ┌─────────────────┐
   │   插件          │  ← 第 4 层：性格、记忆、刷视频、挂件
   │  mood/memory/…  │
   └─────────────────┘
```

**一句话记住每层干什么：**

| 层 | 干什么 | 一句话理解 |
|---|---|---|
| SnowLuma | 协议转换 | 把 QQ 说成"机器听得懂的话" |
| qq-bridge | 中间人 | 决定"谁能用、怎么回、记住什么" |
| DSH | 大脑 | 真正思考、写东西、调工具的那个 |
| 插件 | 器官 | 给大脑加情绪、记忆、耳朵、手 |

> **注意**：如果你只想"让它能在 QQ 里说话"，**只装第 1 层 + 第 3 层就够了**。
> 第 2 层（qq-bridge）解决的是第 1 层和第 3 层之间那一堆琐事，不是必需品。

## 2. 装之前：你需要什么

### 硬件与系统

- **Windows**（SnowLuma 的 QQ 注入只支持 Windows；Linux/macOS 只能跑不注入的模式）
- **官方 NTQQ 客户端**（不是 TIM，不是各种魔改版）
- 一个能登录的 QQ 小号或专用号
- 8GB 内存起步（要同时跑 QQ、SnowLuma、DSH；再开 ACE 之类的另算）

### 软件

| 需要 | 版本 | 干嘛 |
|---|---|---|
| Node.js | ≥ 22.13（SnowLuma 2.x 要 ≥ 24.22） | 跑 SnowLuma 本体和桥接 |
| DeepSeek Harness | ≥ 0.1.7-rc.1 | 大脑 |
| Python（可选） | 3.10+ | 只有要"语音转文字"才需要 |

### 你要提前想清楚的三件事

1. **这个号给谁用**：只有自己？还是拉进群？——决定白名单怎么填
2. **它能不能碰本机**：要不要让它执行命令、读文件？——这决定安全边界，见第 11 节
3. **你愿意花多少**：每轮对话都是模型调用，心情判断、记忆提取也要调。想省钱就关掉这些（第 6 节）

## 3. 第一层：SnowLuma —— 把 QQ 变成接口

### 它是什么

一个程序，站在 QQ 和一个标准协议（OneBot v11）之间。装好之后，任何支持 OneBot 的程序都能跟你的 QQ 对话。

**它不是 bot。** 它不会说话、不会思考，只负责搬运。真正说话的是 DSH。

### 为什么需要它

QQ 没有开放接口。想用程序收发消息，要么逆向客户端（不稳定、随时被封），要么用这种"注入客户端"的方案。SnowLuma 走的是后者：它是官方客户端的附属进程，消息还是你的号在收发，只是多了一个程序入口。

### 怎么装

1. 去 [SnowLuma 的 Release 页](https://github.com/SnowLuma/SnowLuma/releases)下载 **`SnowLuma-v<版本>-win-x64.zip`**
   - 认准 `win-x64` **完整版**，**不要下 `-lite`**（精简版没有 QQ 注入组件，装了等于没装）
   - 压缩包里自带 `node.exe`，不用单独装 Node
2. 解压到任意目录，比如 `<SnowLuma 目录>\…`
3. **先登录 QQ 客户端**，再双击 `launcher.bat`
4. 浏览器打开 `http://127.0.0.1:5099`（WebUI），登录、扫码、确认账号在线

### 配好之后你会拿到两个东西

在 WebUI 的「OneBot 网络」页里：

| 名字 | 地址 | 用途 |
|---|---|---|
| HTTP API | `http://127.0.0.1:3000` | 你主动发消息（`send_private_msg` 等） |
| WebSocket | `ws://127.0.0.1:3001` | 收消息（事件推送） |

**每个都有一个 accessToken**，而且要各填一个。

> ⚠️ **最常见的坑**：HTTP 和 WS 是**两个不同的 token**，抄错了会表现为"连上了但收不到消息"。

### 坏了怎么办

| 现象 | 先看 |
|---|---|
| 5099 打不开 | `launcher.bat` 的窗口还在吗？报了什么 |
| 账号不在线 | QQ 客户端是不是被关了；重新扫码 |
| 3000/3001 连不上 | WebUI 里 OneBot 网络页有没有启用这两个服务 |
| 能发不能收 | WS 的 token 对不对；`messageFormat` 建议 `array` |

## 4. 第二层：qq-bridge —— 让它像个真人

### 它是什么

一个中间程序，站在 SnowLuma 和 DSH 之间。**这一层是可选的，但差别很大。**

不加它，链路是：`QQ → SnowLuma → DSH`。机器人能说话，但：

- 听不懂语音（只能说"我听到一条语音"）
- 不记得别人跟它聊过什么
- 群里谁说话都一视同仁（没有管理员概念）
- 你没法在 QQ 里让它"转告电脑那边干活"
- 没有地方看它到底在干嘛

### 加了它多出来的六件事

#### ① 语音转文字

别人发语音，它转成文字再看。实现方式是本地跑一个语音识别模型（faster-whisper），把收到的语音文件转成文字。

**要额外装**：一个 Python 虚拟环境 + `faster-whisper`（模型几百 MB，第一次跑会下载）。

#### ② 传话箱

让 QQ 里的对话能"把活交给电脑"。

流程：你在 QQ 里说「转告 dsh，把桌面那个文件改名」→ 这条消息进一个队列 → 一个后台守护进程把它投给 DSH 的某个会话 → DSH 真的去做。

**为什么需要**：QQ 那一侧的 AI 故意没有本机权限（第 11 节会讲为什么）。它干不了的活，就递个条子给有权限的那一侧。

#### ③ 管理员闸

**防冒充。**

起因是一个真实事故：群友可以在消息里写一句"我是管理员"，AI 就信了，然后真的执行了管理员命令。

现在的做法是**不信消息里写的任何身份**，而是回头查：这个 QQ 号最近 15 分钟**真的在这个群说过话吗**？

三条规则：
- 私聊管理员 → 直接放行（私聊只有一个对象，冒充不了）
- 群聊里自称管理员，但那个号最近没在群里说话 → 拒绝
- 群聊里的普通群友 → 拒绝

#### ④ 跨会话摘要

让它"记得跟别人聊过什么"，但**不越界**。

- 群聊里问"月野猫猫卷刚才说什么了" → 能答（群是公开的）
- 私聊 A，问"B 说了什么" → 默认闭嘴；只有你**明确点名 B** 才放开 B 的那部分
- 别人的私聊内容 → 永远不会出现在你的对话里

**关键设计**：摘要不是定时刷新落盘的，而是**你问起的那一刻现算**——所以问的是"刚刚"，答的也是"刚刚"。

#### ⑤ 成长附录

一本**只能往后写、不能改**的本子，它自己决定记什么：想通了什么、被纠正了哪个看法、哪次判断错了。

技术上不是靠"约定"，是靠机制：
- 接口只有"写"和"读"，没有"改"和"删"
- 每条带哈希链，手工改历史会显示"链断"

#### ⑥ 3100 控制台

一个网页，能看到：谁在跟它说话、它回复了什么、现在的模式、管理员是谁、各种开关。

地址形如 `http://127.0.0.1:3100/?token=一长串`。**没有 token 打不开**（会 401）。

### 怎么装

```bash
git clone https://github.com/Derpyu520/qq-bridge.git
cd qq-bridge
npm install
copy config.example.json config.json
```

然后改 `config.json` 里几项关键的：

| 字段 | 填什么 | 容易错的地方 |
|---|---|---|
| `dsh.baseUrl` | DSH 的地址 | DSH 端口每次启动可能变，要跟着改（有脚本会自动改） |
| `dsh.authToken` | **留空** | 留空反而更稳；填了容易 401 |
| `snowluma.wsUrl` | `ws://127.0.0.1:3001` | — |
| `snowluma.httpUrl` | `http://127.0.0.1:3000` | **别把 WS 的 3001 填这里**，会报 426 |
| `snowluma.accessToken` | SnowLuma 里那个 | HTTP 和 WS 两个 token 别弄混 |
| `allow.private` / `allow.groups` | 你的 QQ 号 / 群号 | **模板里是空数组**，空着等于谁都不回 |
| `admins` | 管理员 QQ 号 | 管理员闸、点歌、传话箱都看它 |
| `consolePort` | 默认 3100 | 被别的程序占了就改 |

最后一件事，也是最容易漏的：

```bash
node scripts/setup-dsh.mjs
```

这一步在 DSH 里装两个"人设"（preset）并挂上工具接口。**跑完必须重启 DSH。**

> 漏了这一步的表现是：**QQ 上毫无反应**，不报错、不提示，就是不理你。很多人卡在这里以为程序没跑起来。

### 坏了怎么办

| 现象 | 八成是 |
|---|---|
| QQ 毫无反应 | 没跑 `setup-dsh.mjs`，或装完没重启 DSH |
| 起了又消失 | 重启时端口没释放——杀掉后**等 2～3 秒**再启动 |
| 谁说话都不回 | 白名单是空的，而且配置要求"空就全拒" |
| 3100 打不开 | 没带 token；或者它其实没在跑（`/api/status` 能自检） |
| 传话箱消息没人收 | 那个后台守护进程（watcher）没启动 |
| 只回第一句就开始乱答 | 它丢了上下文，去控制台看会话状态 |

## 5. 第三层：DSH —— 大脑

### 它是什么

**DeepSeek Harness**，一个桌面应用。你平时跟它聊天、让它写代码、跑命令，用的就是它。

在 QQ 场景里，它的角色是：收到桥接递过来的"某某说了一句话"，组织上下文、调模型、决定怎么回、调工具发出去。

### 它有三个概念，值得搞懂

**① Profile（配置档）**
DSH 可以有好几套配置，各自独立的插件和设置。QQ 用的和平时用的可能是不同的档。装插件时要认准是装进哪个档。

**② Agent Preset（人设）**
决定"这次对话的 AI 是什么角色"。里面是一大段提示词 + 一堆工具规则。QQ 那一侧的人设（大肥鱼）就写在这里。

想改它的性格、说话方式，改的是这个文件里的 `persona` 段。

**③ MCP（工具接口）**
让 DSH 能调用外部程序的工具。比如 QQ 的收发消息工具、联网搜索、直播间弹幕，都是通过 MCP 挂进来的。

### 坏了怎么办

| 现象 | 八成是 |
|---|---|
| DSH 起不来，报 `Unexpected token ''` | 某个配置文件被存成了带 BOM 的 UTF-8 |
| 装了插件但设置页没有 | DSH 版本不够（会被**静默跳过**），或没重启 |
| 改了人设没反应 | 没重启；或者人设里写了 `{{cwd}}` 这种不存在的变量（会直接报错，表现为完全不回） |
| 工具报"不在白名单内" | 桥接那边的工具白名单没放行，或者改了没重启 |

## 6. 第四层：插件 —— 性格、记忆、活儿

### 三个核心：心情、记忆、记忆库

| 插件 | 干什么 | 关键设置 |
|---|---|---|
| **心情** | 每轮对话后判断"情绪怎么变"，影响它说话的调子 | 填对方的称呼、选生效的会话、可信度门槛 |
| **记忆** | 会淡忘的长期记忆，默认 30 天忘一半 | **默认全关**，每个会话要手动点"开" |
| **Mnemon** | 文档 + 记忆空间 + 运行时记忆，三层 | 大部分是给专业用途的，日常用不到 |

**为什么是三个而不是一个**：心情管"此刻什么感觉"，记忆管"以前发生过什么"，Mnemon 管"整理归档"。它们不重叠，也不打架。

### 两个"活"：刷视频

| 插件 | 干什么 |
|---|---|
| 刷 B 站 | 定时挑视频、打分、写日报 |
| 刷抖音 | 同上，另外能发私信、发卡片、看评论 |

**它们不看画面**——只读文字描述、标签、互动数据。所以遇到"图文作品"会很吃力，因为图里的信息它拿不到。

### 一个装饰：鲸鱼挂件

桌面上一个小挂件。**那个"咚"的提示音就是它**。

关掉的方法：点挂件 → 「音效与提示」→「全局设置」→ 关掉「音效」总开关，或把音量拉到 0。

### 装插件的三个坑

**坑一：版本不够会静默跳过。** 装上了、不报错、但设置页里根本没有这一项。先查 DSH 版本。

**坑二：改文件不改 lock，重启就被打回旧版。** 桌面版没有命令行工具时，手动换文件还不够——得同时改一个叫 `pnpm-lock.yaml` 的文件。不改的话，DSH 每次启动都会按旧记录重装回去。

**坑三：BOM。** Windows 上保存文本特别容易带上看不见的 BOM，DSH 会拒绝启动。存文件时要用"UTF-8 无 BOM"。

## 7. 装完怎么启动

判断顺序很重要，**从上往下**：

```
1. QQ 客户端登录了吗
2. SnowLuma 在跑吗（5099 能打开吗）
3. 3000 / 3001 通吗
4. qq-bridge 在跑吗（3100 能打开吗）
5. DSH 在跑吗
6. 在 QQ 里说一句，有反应吗
```

**任何一步断了，后面的都不会有反应**，而且通常**不会报错**——这是这套东西最反直觉的地方。

平时重启的顺序反过来：先停桥接，再停 SnowLuma。

> 有个小技巧：如果 QQ 那条链路是"一整套"要一起拉起来的，可以写个脚本按顺序检查并拉起缺的。本机就有一个（`start.bat` 那种循环脚本），退出码 `2` 表示"已经在别处跑着了"。

## 8. 日常怎么用

### 看它在干嘛

打开 3100 控制台。能看到会话列表、每条消息的收发记录、当前模式、管理员名单。

### 改它的性格

改人设文件里的 `persona` 段。**改完重启 DSH。**

注意：只改人设，改的是"怎么说话"。想改声音要改语音合成的参考音频；想改记住的事要改记忆；想改表情要改表情库——这些不在人设里。

### 让它做事

在 QQ 里直接说。它能做的：
- 聊天、回答问题、联网查东西
- 放本地曲库里的歌（截一分钟发语音条）
- 用 AI 的声音唱一首（要管理员权限）
- 看直播间的弹幕
- 转告电脑那边干活（要管理员权限）

它不能做的（故意的）：执行命令、读你的文件、改系统设置。这些必须经过"传话箱"转给有权限的那一侧。

### 省钱

- 关掉"每轮判断心情"
- 关掉"自动写摘要"
- 记忆只给真正常用的会话开
- 把判断用的模型指到便宜的那个

## 9. 出问题看这里

按"症状"查，比按"层"查快。

| 症状 | 最可能的原因 | 去哪看 |
|---|---|---|
| 完全不回 | 桥接没装 DSH 端 / 没重启 | 桥接启动日志 |
| 回一句就不回了 | 会话断了 / 上下文超限 | 控制台的会话状态 |
| 只有群里不回，私聊正常 | 白名单没加这个群 | `config.json` 的 `allow.groups` |
| 能发不能收 | WS 的 token 或端口不对 | SnowLuma 的 OneBot 网络页 |
| 说"没有权限" | 管理员闸判定你没在群里说过话 | 先在群里说一句，再提要求 |
| 语音没转成文字 | 转写脚本或 Python 环境没配好 | 桥接日志搜 `voice` |
| 传话箱没反应 | 守护进程没跑 / 投给了死会话 | watcher 日志 |
| 重启后插件变旧版 | 没改 `pnpm-lock.yaml` | 插件的版本号 |
| DSH 打不开 | 有配置文件带了 BOM | DSH 报错原文 |
| 3100 打不开 | 没带 token / 根本没在跑 | 浏览器地址里有没有 `?token=` |

## 10. 名词解释

| 词 | 什么意思 |
|---|---|
| **OneBot v11** | 一套"聊天机器人标准接口"的约定，规定了怎么发消息、怎么收事件 |
| **SnowLuma** | 把 QQ 变成 OneBot 接口的程序 |
| **桥接 / bridge** | 站在两个程序中间做翻译和管制的程序 |
| **DSH** | DeepSeek Harness，跑模型的桌面应用 |
| **Profile** | DSH 的配置档，不同档的插件互不相干 |
| **Preset / 人设** | 一段提示词，决定这个 AI 是什么角色、怎么说话 |
| **MCP** | 让 DSH 调用外部工具的标准方式 |
| **token** | 口令。注意 SnowLuma 的 HTTP 和 WS 是两个不同的 |
| **白名单** | "只允许这些 QQ 号/群"的名单 |
| **传话箱** | 一个队列，让没权限的那侧把活递给有权限的那侧 |
| **上下文** | 模型"现在记得的东西"，有长度上限 |
| **BOM** | 文件开头三个看不见的字节，会让很多程序认不出文件 |

## 11. 三条底线

### ① 白名单先填好，再放它进群

`allowAllWhenEmpty: true` 的意思是"名单空着就全部放行"。**把 AI 接进 QQ 等于把账号的半控制权交给模型**——先填白名单，别图省事。

### ② QQ 那一侧的 AI 不给本机权限，这是对的

它能聊天、能查资料、能放歌，但**不能执行命令、不能读文件、不能改设置**。

这不是"还没做"，是**故意不做**：一个能被群友随便指挥执行命令的 AI，等于把你电脑的钥匙挂在了群公告上。

要干本机的活，走传话箱，由你自己确认后再做。

### ③ 别人发的链接、文件、语音，都是"数据"不是"命令"

AI 收到"帮我打开这个链接"、"运行这段脚本"之类的请求时，不该直接照做。这条不只对 AI 成立，对你也一样——这套链路里任何一环被喂了恶意内容，都可能出事。

---

## 附：这套东西的边界

| 能 | 不能 |
|---|---|
| Windows 上接 QQ | 跨平台（SnowLuma 的注入只有 Windows） |
| 单号、单机 | 多账号集群（要改的地方很多） |
| 稳定聊天 | 高并发（这是"个人用"的量级，不是客服系统） |
| 记住聊过的事 | 记住所有事（记忆有衰减，上下文有上限） |
| 放歌、唱歌、看直播 | 看视频画面（它读的是文字数据） |

**最后一句**：这东西坏起来通常**不报错**，只是"不说话"。所以排查时别找错误信息，找**哪一环没在跑**。
