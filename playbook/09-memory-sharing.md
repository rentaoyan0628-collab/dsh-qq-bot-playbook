# 共享记忆：让群、私聊、换模型之后看见同一件事

> **身份说明**：我不是这些工具的作者，只是一个把它们串起来的普通用户。
> 本文件讲到的每个项目，作者和仓库都在 [README](../README.md#谁写了什么) 里列明了。
> 装的时候请去原作者仓库装；写错了算我的，好用的是他们的。

> **这份不是代码，是设计说明书。**
>
> [07](07-experience-archive.md) 讲的是「怎么让它记得住人」，[08](08-operations-layer.md) 讲的是「怎么让它少说话还不失忆」。
> 这一篇讲第三件事：**同一只 bot 同时活在好几个会话里（群、私聊、不同的群），甚至中途换了模型，它凭什么还知道同一套事情。**
>
> 这里没有可直接抄的路径。要带走的是几张判断表：哪一层记什么、谁看得见、什么时候该写、什么绝对不能写。

---

> ## ⚠️ 先看这一段：这些大多是「拓展插件」，不是 DSH 原生功能
>
> DSH 原生给你的只有两样：**会话上下文**和**热记忆（那两个 Markdown）**。本篇其余的东西——记忆空间、会淡忘的长期记忆、心情、经历库、跨会话摘要——**全部来自拓展插件或本地定制**，要单独装、单独配、单独授权。
>
> 所以给别人的大肥鱼看这篇时，有一条必须写进它的规矩里：
>
> > **凡是要装拓展插件（记忆、心情、刷视频、直播、任何第三方插件），必须先跟主人说清楚「装什么、写哪些数据、要什么权限、怎么卸」，等主人明确同意再动手。没同意就不装，也不要「先装上再问」。**
>
> 这不是客气话，是这套东西的实际风险：记忆类插件会把你的聊天内容写到本机文件或本地数据库；心情类插件会持续读你的对话做判断；直播类插件会用你的账号往别人的房间里说话。**没有一条是「装错了删掉就行」的。**
>
> 下面每一节标题后面，我都标了它是 `[原生]` 还是 `[拓展插件]` / `[本地定制]`，方便你先判断要不要问。

## 痛点：四个「记忆」各管一段，谁也不管全局

先把事实摆清楚。DSH 里的记忆不是一个东西，是四种，而且它们互相不通：

| 已有的东西 | 它记的是什么 | 换会话还在吗 | 换模型还在吗 |
|---|---|---|---|
| 会话上下文 | 这次对话最近的若干条 | ❌ 换会话就没了 | ❌ 换会话等于没了 |
| 交接摘要（四百字） | 这次聊了什么 | ✅ 跟着新会话走 | ✅ 摘要是文字，与模型无关 |
| 记忆插件（会淡忘的） | 你告诉它的事实 | ✅ 磁盘上，按人/按条 | ✅ 与模型无关 |
| 桥接的 recentMessages | 每个会话最近若干条 | ❌ 只在自己会话里 | ✅ 但只在桥接这一侧 |

于是常见三种翻车：

1. **群和私聊像两个人**：私聊里答应的事，群里问起来一脸茫然。
2. **换模型像换了个人**：切到另一个模型之后，之前那些「记得的事」还在磁盘上，但新会话手里没有任何一条。
3. **记得住事实，记不住事**：知道对方养猫，但不知道上周三凌晨聊到几点、答应了什么。

结论：**记忆不是一个插件能解决的事，是一套分层。** 分层做对了，换会话、换模型都只是「重新取一次」。

## 设计：三层，各写各的，互不越权

> 标记：热记忆 `[原生]`｜记忆空间 `[拓展插件]`（Mnemon 那一套）｜原文层 `[本地定制]`（自己写的小服务 + 查询工具）

| 层 | 放什么 | 谁写 | 谁读 | 典型载体 |
|---|---|---|---|---|
| **热记忆** | 短、稳定、每轮都要用的事实与规矩 | 人 + 模型（受容量限制） | 每一轮无条件注入 | 两个 Markdown 投影（用户档案 / 工作参考） |
| **记忆空间** | 可检索的中长期知识：事实、决定、经验、项目文档 | 模型按需写入 | 按问题召回 | Mnemon 的 memory space / documents |
| **原文层** | 「谁、什么时候、说了什么」 | 采集器自动写 | 只在被问到时查 | 经历库（两级：原文 + 经历摘要） |

三条硬规矩：

- **热记忆只放「每轮都必须知道」的东西。** 它是有容量上限的，塞满会自动压缩，压缩就会丢细节。凡是「查一下就有」的，都不该进这里。
- **记忆空间放「事实」，不放「流水」。** 一条记忆应该是一件事、一个属性、一个约定；「今天聊了这些」属于原文层，不属于这里。
- **原文层只做搬运，不做归纳。** 归纳交给「经历」那一层，原文保持原样，才能被追问、被纠错、被引用。

### 为什么原文层不能用「插件」做

插件适合「每轮都要参与的判断」（心情、唤醒、语气）。原文采集是**旁路**：它一直在后台写，绝大多数轮次根本不读它。做成插件会让它挤进每次对话的注入里，白烧上下文；做成独立的小服务 + 几个查询工具，只有真的被问到才动。

## 跨会话：三个共享物，各解决一句话

> 标记：共享摘要 `[本地定制]`（桥接侧代码）｜成长附录 `[本地定制]`｜人物档案 `[拓展插件]`（记忆系统自带的按人视图）

### 1. 共享摘要：解决「别的会话不知道刚才发生了什么」

每个会话在说完一段之后，写一到三句给「别的会话」看的摘要。关键设计：

- **只写结论和状态，不写对话**：写成「今天在弄直播插件，卡在鉴权，晚上继续」，不写「他说……我说……」。
- **不跨隐私边界**：私聊的内容可以变成「最近在忙 X」，不能变成「某人说 Y」。
- **不带路径、不带密钥、不带原文**：这是给所有会话看的，等于半公开。

### 2. 成长附录：解决「它自己变了没有」

只追加、不可改、每条带哈希链。写的是「想通了什么、被纠正后改了哪个看法、哪次判断错了」。

为什么值得单独一份：**这类东西不属于任何一个人，也不属于任何一个会话，属于它自己。** 而且必须是 append-only —— 一旦允许改，它就只会留下「正确」的历史，那这份记录就没有意义了。

### 3. 人物档案：解决「同一个人的事散在各处」

按人聚合，一页一页给，带来源和日期。两条纪律：

- **同名不合并**：宁可多两条，不要张冠李戴。
- **本人问自己才给原文，别人问只给摘要**。这条是整套记忆里最不能妥协的一条。

## 换模型：记忆在磁盘上，不在模型里

这是最容易被误解的一点。切模型（比如从 A 家换到 B 家）**不会**丢掉任何记忆，因为：

- 热记忆是磁盘上的两个文件，每轮重新注入；
- 记忆空间是本地数据库；
- 原文层是本地库；
- 共享摘要、成长附录、人物档案也是磁盘上的。

真正丢的只有一样：**这个会话自己的对话历史**。而它本来就在切模型时被新会话替代 —— 所以正确做法不是「保住旧会话」，是「把旧会话压成摘要交给新会话」。

### 交接摘要的三个坑

| 坑 | 现象 | 做法 |
|---|---|---|
| 摘要被截断 | 每条摘要都恰好一百二十字，明显被砍 | 别从「会话投影」里读回复，那条路有长度上限；走事件流把整段文本拼出来 |
| 摘要注入太多次 | 每轮都重复同一段摘要，白烧上下文 | 给摘要加「配额」，比如只注入前三次唤醒，用完即删 |
| 旧会话被「复活」 | 明明退掉了，重启后又捡回来继续用 | 退掉会话要同时清台账和历史备份，只删当前映射不够；归档 ≠ 从列表消失 |

## 写哪一层：一张决策表

| 你想记的东西 | 写哪 | 理由 |
|---|---|---|
| 「对方养了只橘猫」 | 记忆空间（带事实键） | 稳定事实，会变，要能被最新值覆盖 |
| 「对方最讨厌被叫全名」 | 热记忆（用户档案） | 每条回复都该生效的偏好 |
| 「今天凌晨聊到三点，说下周要考试」 | 原文层 + 一条经历 | 一次性的事，但以后会被追问 |
| 「它昨天把一个玩笑开过了头」 | 成长附录 | 关于它自己的判断，只追加 |
| 「这个项目的插件版本和踩过的坑」 | 记忆空间里的项目文档 | 长、结构化、按需查 |
| 「刚跟 A 说了 B 的私事」 | **哪都别写** | 写下来就等于准备外泄 |

### 事实键（唯一一个需要教模型的细节）

「会变的值」需要一个稳定的键，否则同一件事会堆成十条互相矛盾的记忆。经验是三条：

- **键里不写值**：写「身高」，不写「身高一百七」。
- **键要一年后还成立**：写「睡姿」，不写「最近的睡姿」。
- **万能键禁用**：「相关」「其他」「的事」这种什么都装得下的键，等于把十条不相干的话收成一条。

反过来，**一次性的事不要给键**。给错键比不给键的破坏大得多：它会静默地把旧记忆标成「已被取代」。

## 坑（都是真踩过的）

1. **软重置不重置上下文**。桥接的「清除上下文」如果只是删映射，重启后会被「沿用已有会话」捡回来，看起来重置了其实没有。要重置就连台账一起清。
2. **重置会顺手清掉桥接侧的记忆**（群印象、话题、未读、唤醒配置），因为它跟会话是绑一起的。重置前先想清楚这一条。
3. **心情/记忆插件的「槽位」配错会静默失效**。工作区模式但工作区为空时，它扫不到任何会话，结果只剩衰减：情绪一路往下掉，不报错、不提示。判断办法是看它有没有「新消息触发的更新」，只有衰减就是配错了。
4. **图片与文件不进记忆**。记忆里只放「有过这张图」和它的编号，别把二进制塞进去，也别把本机路径写进去 —— 那既撑爆容量又泄隐私。

## 装之前：先让主人点头

这一节是写给「别人的大肥鱼」的。你自己装无所谓，但**替别人装**时，下面这条是硬规矩。

### 规矩

```text
1. 先说清楚要装什么：插件名、来自哪个仓库、作者是谁。
2. 再说清楚它碰什么：会读哪些内容、会写到哪个文件或数据库、要不要联网、要不要账号。
3. 再说清楚代价：占多少磁盘、要不要常驻进程、会不会每轮都调用模型（=要花钱）。
4. 再说清楚怎么反悔：怎么关、怎么卸、卸掉之后已写的数据还在不在。
5. 然后停下来等主人明确说「装」。没说装，就不装。
```

### 可以直接复制给主人的一段话

```text
我想装一个拓展插件来补记忆能力，先说清楚再动手，你同意我再装：

· 装什么：<插件名>，作者 <作者>，仓库 <地址>
· 补什么：<一句话，比如「让我记得住每个人的稳定信息」>
· 它碰什么：会读 <哪些对话>，写到 <本机哪个文件/数据库>，<要不要联网 / 要不要账号>
· 代价：<磁盘占用>，<是否需要常驻>，<是否每轮调用模型（要花 token）>
· 怎么卸：<关掉的开关> + <卸载命令>，卸掉后已有数据 <保留 / 删除>

你同意的话我就装，装完我会告诉你装到哪、怎么验证生效；不同意我就不动。
```

### 哪些要先问，哪些不用

| 动作 | 要不要先问 | 为什么 |
|---|---|---|
| 读文档、看仓库、跑只读检查 | 不用 | 没有副作用 |
| 装任何拓展插件 | **必须问** | 会写数据、会常驻、可能要钱 |
| 打开「自动记住」「自动总结」这类开关 | **必须问** | 等于同意它持续读你的聊天 |
| 把已有记忆导进去 / 清空 | **必须问** | 不可逆 |
| 自己写一个本地小服务（不进插件市场） | **必须问** | 一样会常驻、一样会写盘 |
| 调整频次、阈值这类参数 | 说一声即可 | 可回退 |

### 一句话总结

**拓展插件不是「装个功能」，是「让它多一双眼睛和一个笔记本」。** 眼睛看什么、笔记本写哪、谁能翻，都得主人先点头。
## 一分钟自检

装完之后，按这四步验证「共享」是真的通了：

1. 在私聊里说一件具体的事（带个只有你知道的细节），然后在群里问「我刚才跟你说什么了」—— 它应该能说出那个细节，或者明确说「那个是私聊，我不往外说」。
2. 换一个模型，重开一个会话，再问同一件事。
3. 让它记一条会变的事实（比如体重），再说一个新值，问它旧的还在不在 —— 应该只剩最新那条。
4. 重启整条链路，再问一次第 1 步的事。

四步都过，才算「跨会话、跨模型、重启后还在」。任何一步失败，先看是三层里哪一层没写进去，不要急着换插件。
