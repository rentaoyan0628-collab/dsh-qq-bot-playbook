# 运营层：怎么让它少说话、省钱、还不失忆

> **身份说明**：我不是这些工具的作者，只是一个把这些东西串起来的普通用户。
> 本文件讲到的每个项目，作者和仓库都在 [README](../README.md#谁写了什么) 里列明了。
> 装的时候请去原作者仓库装；写错了算我的，好用的是他们的。

> **这份不是代码，是设计说明书。**
>
> [06](06-custom-features.md) 是功能补丁，[07](07-experience-archive.md) 是记忆。这一篇是我在真跑了一个月之后补的一层：
> **人设调好、功能都通了，天天出问题的就变成了运营。**
>
> 它太爱说话、在峰价时段乱说话、换班之后忘事、看门狗自己卡住半小时。这四件事都不会报错，只会让你慢慢觉得"这玩意儿不太行"。

## 一、只在被 @ 时醒：把「主动」钉死

### 痛点

有的群里它就该是个安静的成员：被人点到才说话，不点评、不接话、不主动冒泡。但"少说话"这个要求，靠人格里写「你要克制」是不成立的——**人格是建议，不是约束**。它每轮都能自己调工具改唤醒条件，改完还觉得自己很克制。

### 设计

分两处管：

| 层 | 归谁 | 能不能被模型改 |
|---|---|---|
| wakeConfig（mode、triggers、probability） | 模型自己调 | 能 |
| **wakeOverrides（运营方设定）** | 人写在配置里 | **不能** |

后者是硬锁。开了 mentionOnly 之后，每次把配置交给模型之前**强制合并一遍**：

```
mode → diving
atMention → true
nameMention / question / poke / anyMessage → false
keywords → []
speakerIds → []
probability → 0
```

每一次覆盖都打日志：

```text
[reserved2] 唤醒配置按运营方设定钉住 group:xxxxx：mentionOnly → mode=diving
[reserved2] 唤醒配置按运营方设定钉住 group:xxxxx：mentionOnly → probability=0
```

### 坑

1. **只在「设置时」拦是没用的。** 模型可以在任何一轮重新调 set_wake_config，把你刚关掉的开关打开。拦截点必须在「**应用配置**」这一步（每次取配置都过一遍覆盖函数），而不是「收到设置请求」那一步。
2. **定时唤醒那条路根本不读模型配置。** 这是真出过的 bug：会话已经钉成 probability=0，还是被「主动机会」的叫醒器叫起来说话。
   根因是那段代码只读全局概率（配置里的 proactive.probability），从来没看会话自己的 wakeConfig 和 overrides。
   **修法：两道闸。** 一道放在唤醒入口（识别到主动唤醒就直接 return），一道放在概率计算处（mentionOnly / probability<=0 → 概率归零）。只修一处，另一条路照样漏。
3. **布尔判断要写全等。** `if (ov.mentionOnly)` 会把字符串 "false" 当成真。一律 `=== true`。
4. **别拿「它答应了」当验证。** 它会在回复里说"好的我以后不主动了"，然后下一轮照旧。只认日志里那两行覆盖记录。

### 验证

看日志：

- `唤醒配置按运营方设定钉住 … mentionOnly → mode=diving`
- `跳过主动机会唤醒 … 运营方设定只允许被 @`

两条都在，说明两道闸都活着。

## 二、峰价时段睡觉：把预算花在刀刃上

### 痛点

API 有峰谷价。闲聊一句话不值峰价的钱，但定时心跳、主动冒泡不会自己知道「现在是贵的时候」。

### 设计

一个「睡觉」状态，跟人的作息分开：

| 项 | 默认 | 说明 |
|---|---|---|
| peakBilling | 开 | 峰价时段自动进睡觉 |
| 峰价时段 | 09:00-12:00、14:00-18:00（北京时间，工作日） | 写死在常量里，可被配置覆盖 |
| peakRanges | 空 | 自定义时段，形如 09:00-12:00，多条用数组 |
| 睡觉时 | 不主动唤醒，只回被 @ 的 | 压掉的正是"没人找它、它自己找话说"那部分 |
| proactiveProbabilityScale | 0.02 | 睡觉期间主动概率的缩放 |

睡觉不是一个开关，是一个**带原因和结束时间的状态**：进状态时写清为什么（peakBilling / 夜间 / 手动），界面和日志都能看到"它现在为什么不出声、什么时候醒"。

### 坑

1. **自定义时段必须校验。** 用户手写的 peakRanges 里只要有一条格式不对，整个 sleep 配置就可能被判无效——连带把夜间睡眠一起关掉。用正则卡住 `HH:MM-HH:MM`（连字符、波浪号都要认），不合规的丢掉，别让一条坏数据拖垮整块配置。
2. **数字要 clamp。** startHour/endHour/概率缩放这类值，越界的要夹回区间，不要相信配置文件。
3. **睡觉要能一键关。** 调试那几天你会想它随时说话；留一个开关，比临时改代码强。

### 验证

重启后看启动日志那一行：

```text
[sleep] 启动检查：正在睡觉窗口内（peakBilling，xx:xx 结束）／不在睡觉窗口
```

## 三、换班不失忆：交接单 + 原文落盘

### 痛点

上下文满了就得换会话。换完它开口第一句经常是「我们刚才说到哪了」——**摘要只有 400 字，接不住一个聊了两小时的天**。

### 设计

一个接口做三件事：

```
POST /api/session/handoff  { "key": "group:123", "text": "可选，人工写的交接说明" }
  ↓
拼素材：记忆摘要 + 最近 200 条「[时间] 我/对方：正文（截 300 字）」
  ↓
重摘要 → 退役旧会话 → 新会话一开就带着这份摘要
  ↓
同时把这段原文整段追加到 state/memory/<年-月>/<key>.md
```

四个刻意的选择：

1. **原文落盘，纯追加。** 摘要给模型，原文给人。想核对「当时到底怎么说的」，去 grep Markdown，不用问模型。
2. **按年月分目录、按会话分文件。** 一个会话一个文件，越聊越长，但永远只追加、不覆盖。
3. **原文不进上下文。** 它躺在本地，不出网，也不默认读进模型——除非有人明确要求核对。否则每次醒来都先烧几千 token 回忆，纯亏。
4. **已退役的会话也允许重做摘要。** 素材还在，只是不用再退役一次；否则一旦摘要质量不满意，就没法补救。

### 坑

1. **会话 key 里有冒号**（`group:123` / `private:456`），Windows 文件名不允许，必须替换成下划线，否则整个落盘静默失败。
2. **截断要写清楚。** 每条正文截 300 字，长消息会被切；摘要时要说明"这是节选"，否则模型会把截断处当成对方话说一半。
3. **别把令牌、cookie、路径写进落盘文件。** 只存发言者、时间、正文。这份文件是给人看的，不是给攻击者看的。
4. **交接是重操作。** 它要重摘要、退役会话、写盘，别放在消息主链路上同步等；失败要能退回"不交接、继续用旧会话"。

### 验证

1. 调一次接口，看 `state/handoffs.json` 多一条记录；
2. 看 `state/memory/2026-10/group_123.md` 变长，内容是「时间 + 谁 + 正文」；
3. 新会话的第一轮上下文里，应该带着刚生成的摘要。

## 四、看门狗别自己卡住

### 痛点

守护脚本每轮要探好几个端口（网关、桥接、语音、worker）。用 `Get-NetTCPConnection` 探一次要 300 毫秒，机器忙的时候能抖到 1 秒；一轮探十几个端口，光探测就十几秒，看起来像"卡死了"。

### 设计

换成直接连 socket：

```powershell
$c = New-Object System.Net.Sockets.TcpClient
$iar = $c.BeginConnect('127.0.0.1', $port, $null, $null)
if (-not $iar.AsyncWaitHandle.WaitOne(400)) { return $false }
return $c.Connected
```

实测单次 ~5ms，比原来快两个数量级。再加一个「等到端口起来」的轮询（默认 300ms 一次、给个总超时），启动链路就不用靠 sleep 猜。

### 坑

1. **探测只看端口，不看进程名。** QQ 崩溃重启后进程名一样但端口还没起；反过来端口被别的程序占着也会"看起来活着"。端口 + 一次真实请求才算活。
2. **等待要有上限。** 无限重试等于挂死；给总秒数，超时就记一条失败继续往下走。
3. **脚本要能单轮跑。** 加个 `-Once`（跑一轮就退）和 `-Quiet`（不写日志）——测速和排障时你会天天用，没有这两个开关，验证一次就得污染一遍日志。

### 验证

```powershell
Measure-Command { .\dsh-qq-watchdog.ps1 -Once -Quiet }
```

正常应该在一秒以内。如果还是十几秒，说明有别的环节在等（比如某个 HTTP 请求没设超时）。

## 五、几个小改动，差别很大

这些不值得单独成篇，但都是"用起来舒服"和"用起来难受"的分界线：

| 改动 | 为什么值 |
|---|---|
| 历史检索工具（走桥接的搜索接口，带 agent token） | 上下文里只有 100 条，但"上周谁提过这个"要靠全库搜；只读、跟其他只读工具同一个开关 |
| 中文数字点歌（「点三十九」也能认） | 群里没人打阿拉伯数字；解析器要同时认 39 / 三十九 / 第39首 |
| 心情按人分槽 | 心情是"我对这个人的心情"，不是"这个群的心情"；一个群人多了，不分槽就永远是同一个人的情绪 |
| 会话台账 + 空会话重建 | 桥接重启后会话 id 会变；台账记住过哪些，重建时能接回同一个人的历史 |
| 人格第 19 条：同一个人反复说同一件事，第一次关心一句，之后只接情绪 | 这是防它变成安慰机器。反例很具体：人家第三次说腰疼，它第三次建议"要不要试试靠枕、拉伸一下" |

最后一条其实不是代码，是**运营**。写进人格卡的效果比改十行逻辑都大。

## 可以直接发给 AI 的需求

> 我的 QQ 机器人在真群里跑了一段时间，现在要补一层"运营"控制。请在我这台机器上：
> 1. 加一层**运营方唤醒设定**，优先级高于模型自己调的唤醒配置：至少支持「只允许被 @」。要求：在**每次应用配置时**强制合并（不是只在收到设置请求时拦），每次覆盖都写日志
> 2. 检查所有会主动说话的路径（定时主动、补投、重试），确保它们都读这层设定——**只堵一个入口不算完**
> 3. 加睡眠状态：支持"峰价时段自动睡"（时段可配、按 HH:MM-HH:MM 校验，坏数据丢掉而不是整块失效），睡觉时只回被 @ 的；状态带原因和结束时间，能一键关
> 4. 加会话交接：一个接口，把「记忆摘要 + 最近 200 条对话（带时间、带发言人）」重新摘要给新会话，同时把原文**纯追加**到按年月分目录的 Markdown 里（可 grep、不进上下文、不含令牌和路径）
> 5. 交接要能对已退役会话重做摘要；失败能退回继续用旧会话
> 6. 守护脚本的端口探测换成 TcpClient（带超时），加"等端口起来"的轮询，并支持单轮运行 + 静默两个开关
> 7. 人格里加一条：同一个人反复说同一件事，第一次关心一句，之后只接情绪，不再给方案
> 做完告诉我：怎么用一行日志确认「只允许被 @"生效了、交接后的会话确实带着摘要。
